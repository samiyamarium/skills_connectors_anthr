Core Taxonomy & Paradigm Shift

Moving from a plain conversation interface to an Operating Layer transitions AI from an isolated text generator into an active workplace participant capable of contextual reasoning and app-level actions.

Operating Layer Result
  • One-time Prompt: Shouted order across a counter; executed once and immediately forgotten.
  • Skill: Standardized, persistent instruction set pinned to the system, executed identically every time.
  • Connector: The live interface providing safe, authenticated access to external data repositories (e.g., Google Drive, Gmail, Linear, Notion).

Anatomical Blueprint of SKILL.md

A Skill is fundamentally a directory containing a mandatory root file named exactly SKILL.md.

my-skill-folder/          <-- Folder MUST be kebab-case
├── SKILL.md              <-- MUST be capitalized exactly
├── references/           <-- Optional: Deep technical docs (Level 3)
├── assets/               <-- Optional: Static templates & visual guides
└── scripts/              <-- Optional: Deterministic code executed by engine
Progressive Disclosure Mechanics
Level 1: Frontmatter
(Always In-Context / Description)
➔
Level 2: SKILL.md Body
(Loaded on Match / Instructions)
➔
Level 3: Subfolders
(Loaded on Demand / Scripts & Refs)

SKILL.md Skeleton Example:

---
name: client-monthly-summary
description: Prepares a monthly client financial summary for an accounting firm. Use when the user asks for a "client summary", "monthly close", or "month-end report". Do NOT use for quick single-item questions.
---

# Client Monthly Summary Instructions
1. Format all amounts with thousand separators.
2. Flag items exceeding tax-withholding threshold.
  • Kebab-Case Rule: Folder names must use lowercase letters separated by hyphens (e.g., client-monthly-summary).
  • Tag Restrictions: Frontmatter description must NOT contain HTML/XML tags.
  • Reserved Key Terms: Skill names cannot include reserved vendor brand strings like claude or anthropic.

Connector Protocol & Governance (MCP)

Connectors run on the open Model Context Protocol (MCP) standard. They bridge AI models to third-party APIs while enforcing organizational identity and privilege boundaries.

Connector Security Architecture
User Identity Permissions
➔
MCP Connector Scope
➔
Read-Only / Write Guardrails
Parameter Read-Only Mode Write Access Mode
Capabilities Search, read, summarize, extract data. Edit documents, send emails, delete records, post tickets.
Safety Level High (Recommended initial state). Requires established operational trust & recovery checks.
Scope Controls Restricted to explicit folders/channels. Per-action execution confirmation flags.

Tool Access Settings: When managing 10+ active connectors, switch tool loading to load-on-demand to prevent prompt context bloat.

System Feature Comparison Matrix

Understanding the exact functional isolation between all four core system features prevents configuration overlap and unexpected model behavior.

Feature Primary Utility Activation State Mental Shortcut
Skill Reusable, domain-specific procedural instructions. Dynamic (Sleeps until prompt matches description). "I keep re-explaining HOW to do this."
Connector Secure read/write integration with external systems. Session-enabled / Dynamic tool invocation. "I keep copy-pasting from another app."
Project Isolated workspace for specific continuous bodies of work. Static (Always loaded inside project chats). "These files/rules apply to EVERYTHING here."
Custom Instructions Global persona and output formatting preferences. Global (Always loaded across ALL chats). "I want this rule to be true everywhere."

Dynamic Firing & Built-In Engine

The system evaluates prompt intent against frontmatter descriptions to trigger skills dynamically without mandatory manual invocation.

Matching Skill Fires Automatically
  • Firing Trigger: Occurs automatically when user phrasing matches a skill's frontmatter description field.
  • Manual Overrides: Force execution by naming the skill explicitly ("Use my brand-voice skill") or typing / in supported UI surfaces.
  • Negative Triggers: Instructions in descriptions explicitly prohibiting activation for edge cases.
  • Built-in Capabilities: Document skills rely on the engine toggle "Code execution and file creation" under Settings -> Capabilities.

Security Threat Matrix & Safety Audit

Granting tools access to active computational layers and data channels creates explicit attack vectors that require rigorous verification.

Threat Category Mechanism Countermeasure / Audit Rule
Prompt Injection Hidden text inside untrusted skill files overriding system instructions. Audit full text before installing: "Read this skill and flag anything that contacts external servers."
Data Exfiltration Skill silently transferring private context out to third-party endpoints. Disable network egress on execution toggles; limit skill origin to verified directories.
Unscoped Connector Access Granting whole-drive or broad admin privileges to a single connector. Scope connectors strictly to required subfolders; enforce read-only status initially.

Practical Implementation Workflows

Deployment of Skills and Connectors follows a structured methodology centered around the Market-of-One Test: A skill is worth creating only when it captures your own repeated personal or firm-specific procedural workflow.

  1. Project 1: Private Skill Creation: Utilize skill-creator to generate, test frontmatter triggers, and iteratively refine custom instruction formats.
  2. Project 2: Read-Only Connector Integration: Establish zero-copy-paste context pulling from cloud storage or email threads.
  3. Project 3: Skill + Connector Pipeline: Combine automated data fetching with customized procedural output formatting.
  4. Project 4: Standardized Handoff & Portability Test: Distribute SKILL.md across team directories or execute in terminal environments.
  5. Project 5: Third-Party Security Audit: Perform programmatic dry-runs and line-by-line intent checks before deploying third-party community skills.
